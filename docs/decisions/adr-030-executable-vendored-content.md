# ADR-030: Vendored skills may ship executable files, and dev-ready carries the executable bit

- Status: **Accepted** (2026-08-20, CEO Moofon). Targets v0.12. Extends [ADR-008](adr-008-integration-modes-vendor-vs-pinned.md) to content that is not documentation, and is bounded by [ADR-022](adr-022-upstream-config-not-application-source.md), which governs the base template and says nothing about vendored skills. FR-16's byte-for-byte rule is unchanged.
- Context: every skill dev-ready has vendored through v0.11 is Markdown plus a `LICENSE`. The twelve `obra/superpowers` skills FR-47 adds are not. Measured on 2026-08-20 at commit `b36e0829c6d0140e93cfef2ca599b1b07d4a7797`.
  - **Ten of the curated twelve's thirty-eight files are not Markdown**, and six carry mode `100755` upstream: `brainstorming/scripts/start-server.sh`, `brainstorming/scripts/stop-server.sh`, `subagent-driven-development/scripts/review-package`, `subagent-driven-development/scripts/sdd-workspace`, `subagent-driven-development/scripts/task-brief`, and `systematic-debugging/find-polluter.sh`. Four more are ordinary-mode program files: `brainstorming/scripts/server.cjs` at 25,693 bytes is a Node HTTP server, beside `helper.js`, `frame-template.html`, and `systematic-debugging/condition-based-waiting-example.ts`.
  - **The skills invoke those files bare, with no interpreter prefix.** `subagent-driven-development/SKILL.md` says to run `scripts/sdd-workspace PLAN_FILE` (line 137), `scripts/task-brief PLAN_FILE N` (line 252), and `scripts/review-package PLAN_FILE BASE HEAD` (line 290). `brainstorming/visual-companion.md` says to run `scripts/start-server.sh --project-dir /path/to/project --open` (lines 38, 65, 74, 81). `task-brief` opens with `#!/usr/bin/env bash`, so it depends on the kernel reading its shebang, which needs the executable bit.
  - **dev-ready's repository cannot carry the bit by accident.** `git ls-files -s src/dev_ready/templates` returns 162 files, every one `100644`, and the maintainer's machine has `core.fileMode=false`. Syncing here records `100644` before the first commit.
  - **A correct repository would not be enough.** `overlay/__init__.py:197` is the only place generation writes a file, and it is `dest.write_bytes(data)`. Nothing under `src/dev_ready/` calls `chmod`, `copymode`, or `copystat`. The generated file's mode is decided by dev-ready's writer and the process umask — normally `0644` — regardless of what the wheel or the repository holds.
  - So the flow's **first** chain entry and one branch of its fork both issue a command that returns `Permission denied` on any POSIX machine, while `vendored-drift`, which compares content and not mode, stays green.
- Decision: dev-ready ships the files whole and carries the bit to the user's project.
  - **A vendored skill may contain executable files, scripts, and program source.** This is a widening of what dev-ready is willing to place in a user's repository, and it is stated here so it is not re-argued per skill. The limit is unchanged: FR-16 compares directories byte for byte and a skill ships whole or not at all, so trimming a skill's scripts to make it fit is not available.
  - **A vendored pin declares which of its source paths are executable**, and generation applies that mode after writing the bytes. The executable fact lives on a path inside `obra/superpowers`; the write happens at a path inside the user's project. Nothing carries information between those two path spaces today, which is why the declaration is explicit manifest data rather than something derived at either end.
  - **No heuristic decides it.** "Anything under `scripts/`" would mark `frame-template.html`, `helper.js`, and `server.cjs`, which upstream leaves at `100644`. A rule that is right by accident on today's twelve skills is wrong on the next repository vendored.
  - **The guarantee stops at Windows.** `os.chmod` with executable bits does nothing useful there. Upstream already expects a bash environment on Windows — `visual-companion.md:68` says the launcher "auto-detects and switches to foreground mode" — so the result depends on the user's shell, which dev-ready does not control. `docs/agents/superpowers.md` says this plainly rather than implying the fix is universal.
  - **`brainstorming`'s runtime state directory is ignored; its documents directory is not.** `visual-companion.md:56` writes session state to `<project>/.superpowers/brainstorm/`, which is generated output and gains a `.gitignore` line under FR-38's prune-and-replace authority. `docs/superpowers/plans/` and `docs/superpowers/specs/` hold plans and design documents the flow expects to be committed, and are never ignored.
- Considered options:
  - **Shipping the twelve as-is and recording the loss as a known defect** — rejected. It is the cheapest option and it keeps Phase 2 a data-only change. It also makes Phase 2's acceptance criterion — a project holding exactly the twelve vendored skills as Canonical Content — pass while the flow fails at its first step. An acceptance criterion that a release satisfies and a user does not is the specific failure this project spent FR-43 removing.
  - **Telling the user to prefix the commands with `bash`** in `docs/agents/superpowers.md` — rejected as the primary remedy. FR-16 forbids editing the vendored `SKILL.md`, so the correction would live in a different file from the instruction, and it would rely on the agent preferring dev-ready's document over the skill's own line. It stays available as the fallback wording for Windows, where no mode can be set.
  - **Excluding the three skills that ship executables** — rejected. `brainstorming` is the chain head and `subagent-driven-development` is one branch of the fork; removing them leaves a flow that no longer matches the one upstream describes.
  - **Marking modes in the drift check instead of at generation** — rejected as insufficient. It would stop the repository silently losing the bit, which is worth doing, but the user's copy is written by `write_bytes` and would still arrive at `0644`.
- Consequences: dev-ready gains a second write primitive beyond "write these bytes", and `verify` gains a fact it can check that is not content. A generated `superpowers` project contains roughly 47 KB of JavaScript, shell, HTML, and TypeScript that dev-ready did not write and does not test, and a user who accepts the visual companion starts a local HTTP server from it — opt-in per session, since `brainstorming/SKILL.md:96` offers it just-in-time and only on approval, and never offers it when no visual question arises. Node becomes a requirement for that one optional path, in a project whose other requirements are Python and Docker. The `vendored-bump` workflow gains a reason to re-read a skill: a pin bump that changes a file's mode is a change the content comparison cannot see.
