# ADR-028: Agent Targets receive one Skill Link per skill — no copy mode, no Pointer Stub

- Status: **Accepted** (2026-08-18, CEO Moofon). Targets v0.12. **Supersedes [ADR-025](adr-025-skill-delivery-mode.md) in full.** ADR-025 was accepted on 2026-08-12 and never implemented; it stays readable because the reversal it records is itself information. [ADR-015](adr-015-agent-targets-canonical-content-pointer-stubs.md)'s Canonical Content decision is unchanged and load-bearing here, and its Pointer Stub half stays retired.
- Context: ADR-025 chose a recorded user selection between `symlink` and `copy`. Five facts were measured on 2026-08-18, during the v0.12 `grill-with-docs` session and before any code was written. Three of them contradict it.
  - **A junction is visible to git, and that visibility duplicates content.** ADR-025 states that a junction "has no representation in git at all". That is wrong in the direction that matters. Git walks through the reparse point and stages the linked files as ordinary blobs carrying the same content hash as the canonical file. Measured in a scratch repository: a junction at `.claude/skills_jct` produced `100644 51217b3f 0 .claude/skills_jct/foo/SKILL.md`, a duplicate of `.agents/skills/foo/SKILL.md`. A POSIX symlink is recorded as mode `120000` and duplicates nothing. So the elevation-free mechanism ADR-025 reopened the question for is the one carrying a new cost, and only keeping the link out of version control removes it.
  - **A junction cannot be created before its target exists.** `_winapi.CreateJunction` against a missing target raises `FileNotFoundError [WinError 3]`. `dev-ready init` writes into a staging directory and commits it with one atomic rename, so a junction created during the overlay stage stores the staging path and breaks at the rename. Both halves were measured. A relative POSIX symlink survives that same rename.
  - **Python has no public junction API.** `os.symlink` on a directory needs Developer Mode or an administrator on Windows, which is the mechanic ADR-015 was right about. CPython's `_winapi.CreateJunction` is private and undocumented. Node's `fs.symlink(..., 'junction')`, which ADR-025 quotes from the reference installer, has no standard-library counterpart here.
  - **`Path.is_symlink()` returns `False` for a junction.** ADR-025 rests its inventory argument on `upgrade`'s traversal guard (`upgrade.py:33-42`), which calls exactly that. The guard is blind to junctions. dev-ready requires Python 3.12, so `Path.is_junction()` closes the hole, but the guard must call both.
  - **Claude Code discovers a skill through both link kinds.** Verified by hand on 2026-08-18: a project holding `.claude/skills/probe-junction` as a junction and `.claude/skills/probe-symlink` as a relative symlink listed both as project skills, and the symlinked skill was invoked end to end. This premise had no prior evidence — dev-ready has never shipped a link — and every decision below depends on it.
- Decision: there is one delivery mechanism, not a choice between two.
  - **One Skill Link per skill.** Each selected Agent Target's skills directory receives one link per canonical skill: `.claude/skills/<name>` points at `.agents/skills/<name>`. The skill set is projected structurally from the desired overlay content — every direct `.agents/skills/<name>/SKILL.md` entry — rather than from Catalog Item ids, so ADR-026's unconditional, non-catalog `setup-project` participates without a hardcoded exception. One pure helper in `agent_targets` derives names from content paths for generation, verification, `check`, and `upgrade`; no lifecycle consumer keeps its own skill-name list. The target's skills directory itself stays a real directory and is never replaced by a single link, because retiring the Pointer Stubs beneath it would then require deleting that whole directory, taking any skill the user wrote by hand with it — which ADR-014 forbids.
  - **The Agent Target container is a real-path boundary.** If its skills directory or any path component leading to it is a symlink or junction, `upgrade` preserves the redirection, reports one whole-target conflict, and makes no ignore-anchor, legacy-content, or Skill Link change beneath it; `check` reports drift. This remains true when the redirection currently resolves inside the project. Traversing a user-controlled container would let dev-ready mutate paths whose ownership it cannot establish, while replacing it could delete user-authored skills.
  - **A relative symbolic link on macOS and Linux; a junction on Windows.** The relative link survives a project move. The junction needs no elevation, and it is the only elevation-free directory link Windows offers.
  - **No `copy` mode and no Pointer Stub.** Nothing is chosen, so nothing is asked and nothing is recorded: there is no `--skill-delivery` flag, no prompt, and **no stamp field**. The stamp stays at version 5, and v0.12 needs no migration for a new field. Canonical Content is still written unconditionally and still serves every Standard-Compliant Agent.
  - **Links are excluded from version control by a `.gitignore` beside them.** Each Agent Target's skills directory receives its own `.gitignore` naming that directory's links. The project's root `.gitignore` is not touched: it is a file users edit, and `upgrade` refuses to rewrite a user-modified file, so a later Agent Target's links would silently reach the index. The nested file also keeps the directory present after a clone, and carries the bootstrap command in a comment. **Ignore coverage is a precondition for links, not best-effort documentation:** `upgrade` creates, repairs, or converts links in one target directory only when its nested file will be written transactionally or already matches the exact bytes dev-ready generated for the current link state. An identical unrecorded file may be adopted; a differing file is preserved under ADR-014 and blocks every link change and Pointer Stub retirement in that directory until the user reconciles it. A recorded-but-missing anchor is the narrow exception to the ordinary missing-file rule: `upgrade` transactionally restores its exact state-aware bytes, because leaving existing junctions exposed to Git is not a safe preserved state. The report calls that restoration out, including in dry run; an unsafe or non-directory parent remains a conflict. No ordinary overlay file inherits this exception. During a partial conversion, the file names only link objects that will actually exist after the transaction, never a preserved real directory; those exact state-aware bytes enter the inventory. `check` compares the file with the fully desired link set, so partial conversion remains visible as drift, and a later upgrade expands the file in the same transaction that creates the remaining links. Semantic parsing and a runtime dependency on `git` were rejected: only exact generated bytes establish the invariant without reimplementing Git's precedence and negation rules or depending on a global tool.
  - **The nested `.gitignore` is also the ownership anchor for stale derived links.** A later manifest can remove a skill or move an Agent Target path, but the stamp deliberately contains no link paths. When the current file still matches its recorded inventory hash, its generated entries are trusted evidence of the old link names: `upgrade` may transactionally remove a named stale path only when it is still a symlink or junction, and may then update or retire the anchor. A real file or directory is always preserved. A modified anchor preserves every associated stale link and reports conflicts for manual reconciliation. `check` reports stale entries and obsolete managed anchor files as drift. This keeps links out of the stamp without turning a shrinking or moved projection into permanent garbage.
  - **Links are created inside the finalize stage, after the atomic rename, on every platform.** Windows leaves no alternative, and one ordering means one code path and one failure story. `init` still reports exactly four stages. A failure after the rename is handled by finalize's existing target restoration, so generation stays all-or-nothing.
  - **Link support is probed during the verify stage when the selection projects at least one Skill Link.** Staging sits beside the target on the same filesystem, so a link created and removed in staging answers the question for the target. A filesystem that cannot hold links fails there with `VerificationError` — **exit 5** — before anything is written. The message names the path, the cause, and the remedy, because with no `copy` mode the user's only remedy is a different location. An explicit `--agents none` projects no links and therefore performs no link probe: rejecting that project would require a filesystem capability its output never uses, and selection is already deterministic input under NFR-1.
  - **A link is derived state and is never inventoried.** dev-ready recomputes every desired link from the recorded Agent Targets and skills, while the inventoried nested ignore file supplies safe evidence for retiring links that are no longer desired. `check` reports a missing or stale link as drift (exit 7); `upgrade` creates missing links, rebuilds junctions broken by a project move, and retires stale links only through that ownership anchor. The generated `README.md` names `uvx dev-ready upgrade` as the first command to run after a clone.
  - **Canonical Content readiness is a per-skill precondition for changing its link.** The canonical skill directory and its `SKILL.md` must exist after the transaction as real, safe paths inside the project; content being added or upgraded in that transaction counts as ready, and user-modified canonical content remains valid and preserved. A missing recorded file, unresolved collision, or link/junction component blocks that skill's link creation, repair, and Pointer Stub retirement while unrelated skills may proceed. Otherwise `upgrade` could replace a working stub with a link to absent or untrusted content. `check` reports both the canonical-content drift and the resulting Skill Link drift.
  - **The upgrade transaction has one dependency order, and the stamp is its commit marker.** Discovery, conflict classification, and any required link-support probe finish before the first persistent mutation. The transaction then backs up every path it will replace or remove before it writes Canonical Content, writes each exact state-aware nested `.gitignore`, retires eligible legacy agent-local directories, creates or repairs links, and writes the stamp last. A failure at any point restores every affected file, directory, link, ignore anchor, and stamp to its exact pre-upgrade state. This order prevents a link from pointing at unready Canonical Content, prevents a managed link from being exposed to Git, and prevents the stamp from describing a transaction that did not finish.
  - **Existing agent-local skill artifacts retire through ADR-014's obsolete-file rules**, in the same transaction that creates the links. Stamp versions 4 and 5 normally record Pointer Stubs there, while a directly upgraded version 3 project may record a full content copy; the recorded inventory hash, never body-shape detection, decides whether either is untouched. A v3 full-copy directory is one preservation cohort: if every existing recorded file is untouched and no unrecorded entry exists, the whole directory retires even when a recorded file was already missing; if any file is modified or any unrecorded entry exists, the whole directory is preserved, including untouched companion files, so a modified `SKILL.md` is not stranded without its scripts or references. The report names the paths that blocked conversion. Retiring untouched legacy content means deleting its recorded files, removing the emptied directory, and creating the link in its place; `upgrade` today deletes files and never removes directories, so its transaction and its rollback both grow. User-modified legacy content is preserved and reported, and its link is not created. Direct upgrades from every supported origin still finish at stamp version 5.
  - **`CLAUDE.md` keeps `@AGENTS.md` and is out of scope**, unchanged from ADR-025.
- Considered options:
  - **ADR-025's two modes** — superseded. `copy` was retained there as the safe default; removing it is the CEO's decision, made after the junction measurements above.
  - **One link per Agent Target directory** instead of one per skill — rejected. It is fewer links and a shorter ignore file, but converting an existing project requires deleting the target's whole skills directory, which destroys user-authored skills. The chosen option costs at most 972 links in a fully selected project, which is exactly the number of Pointer Stub files such a project writes today.
  - **Committing the links** — rejected. On Windows a junction commits duplicated content that no command manages; on a Windows clone with `core.symlinks=false`, a committed POSIX symlink checks out as a text file holding the link target.
  - **Falling back to `copy` when a link cannot be created** — proposed in session and withdrawn by the CEO. A detected fallback makes one dev-ready version produce different output on different machines, which NFR-1 forbids. ADR-025's rule against a platform-conditional fallback therefore survives its supersession intact.
  - **Adding an exit code for link failure** — rejected. Exit 5 already means the project was not produced and nothing was left behind, and a new code would change `docs/cli-spec.md`, the Generation Skill's documented result list, and every consumer's mapping.
- Consequences: A generated project's agent directories are machine-local by design, on every platform, with no mode that avoids it. A collaborator who clones the repository gets Canonical Content and no agent directory contents until `uvx dev-ready upgrade` runs; `dev-ready check` names what is missing. `setup-project` cannot bootstrap this, because it reaches Claude Code through the same link. A junction's target is absolute, so moving a project on Windows breaks its links until `upgrade` rebuilds them. A filesystem without link support — exFAT, some network shares, some container mounts — can no longer receive a generated project that selects an Agent Target, where v0.11 could, because Pointer Stubs were ordinary files; an explicit `--agents none` project remains possible because it needs no links. dev-ready gains a private-API dependency on `_winapi.CreateJunction` that a test must assert, its first write primitive that is not "write these bytes", and its first `upgrade` transaction step that removes a directory. Because every existing CI job ran only on Ubuntu when this decision was made, v0.12 adds a `windows-lifecycle` job that runs the offline suite plus real generation and the N−1 upgrade gate, including Git exclusion and moved-junction repair; the manual Windows/POSIX clone check remains responsible for proving agent discovery and invocation. The [[Skill Delivery Mode]] glossary entry is retired without ever having shipped, and [[Skill Link]] replaces it.
