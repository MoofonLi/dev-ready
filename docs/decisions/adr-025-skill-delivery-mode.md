# ADR-025: Agent Targets receive a chosen Skill Delivery Mode — symlink or copy — replacing Pointer Stubs

- Status: **Accepted** (2026-08-12, CEO Moofon). Targets v0.12. **Supersedes the Pointer Stub half of [ADR-015](adr-015-agent-targets-canonical-content-pointer-stubs.md)**; ADR-015's Canonical Content decision is unchanged and load-bearing here.
- Context: ADR-015 chose Pointer Stubs over both symlinks and per-agent copies, and its 2026-07-27 amendment rejected symlinks a second time. Two of the three mechanics that decision rested on do not survive measurement, and the ecosystem convention it declined has since been read directly rather than summarized.
  - **"Symlinks require developer mode on Windows" is wrong for directories.** A Windows *junction* (`mklink /J`, `fs.symlink(..., 'junction')`) needs no elevation. The reference installer already relies on this: `installer.ts:255-256` selects `'junction'` on `win32` with an absolute target, and a relative symlink everywhere else.
  - **The convention is an explicit user choice, not a default.** `add.ts:770-800` in `vercel-labs/skills` at pin `1164afa5f0e2` defines `InstallMode = 'symlink' | 'copy'` and prompts `Installation method` — *Symlink (Recommended)* against *Copy to all agents* — whenever the selected agents resolve to more than one distinct skills directory, falling back to `copy` without asking when they resolve to one.
  - What ADR-015's amendment got right survives and is not restated as a rejection: a symlink deduplicates nothing inside a project whose Canonical Content is already inside it. The decision below is therefore not made on deduplication grounds.
  - Two new facts push the other way. A **junction has no representation in git at all**, and a POSIX symlink survives `clone` as a link only where `core.symlinks` is enabled — off by default on Windows. A generated project is meant to be committed and cloned, so a link is machine-local state, not content. And a junction's target is absolute, so it breaks when the project directory is moved or renamed.
- Decision: delivery becomes a recorded selection with two modes, and the Pointer Stub is retired.
  - **Two modes: `symlink` and `copy`.** In `copy`, each Agent Target's skills directory receives the full skill content. In `symlink`, it receives a link to the Canonical Content at `.agents/skills/`. Canonical Content is written in both modes, unconditionally — it serves every Standard-Compliant Agent and is the anchor `upgrade` operates on.
  - **The mode is asked once, and only when it can matter**: when at least one selected Agent Target declares a skills directory other than `.agents/skills/`. dev-ready always writes Canonical Content, so a single non-standard target is already enough for a link to have a real destination — this is where dev-ready's rule departs from the reference installer's, which counts only the selected agents' directories and therefore skips the question at one target.
  - **Non-interactive: `--skill-delivery symlink|copy`, defaulting to `copy`.** The default is the mode that survives `git clone` on every platform.
  - **No platform-conditional fallback.** A `symlink` selection on a system that cannot create the link fails with a message naming the cause. Silently degrading to `copy` would make one dev-ready version produce different output on different machines, which NFR-1 forbids. An explicit user selection is an *input*, so determinism is preserved; a detected fallback is not.
  - **The stamp records the mode**, and the inventory follows from it: in `copy` mode each copy is inventoried by content hash exactly as today; in `symlink` mode the links are **not inventoried at all**. A link is derived state, not managed content — dev-ready manages the Canonical Content the link resolves to. This is also what keeps `upgrade`'s path-traversal guard (`upgrade.py:33-42`, called at `:195` and `:243`) intact: that guard refuses any path traversing a symlink, and with no inventoried path under a linked directory, `upgrade` never presents it with one. `verify` checks that each declared link exists and resolves inside the project.
  - **Pointer Stubs are retired.** Existing generated projects hold stubs recorded in their stamp inventory; those paths retire through ADR-014's obsolete-file rules in the same transaction as the mode is adopted, with user-edited stubs preserved and reported.
  - **`CLAUDE.md` keeps `@AGENTS.md` and is out of scope.** That is Claude Code's native import directive, not a dev-ready indirection, and `AGENTS.md` is the open standard; a second copy of the rules file would be two sources of truth that drift.
- Considered options:
  - **Keeping Pointer Stubs** — rejected by the CEO after the mechanics were re-measured. The stub works: it preserves the canonical frontmatter, and this repository's own `.claude/skills/` stubs are followed successfully in practice. It is retired to match the ecosystem convention the same installer defines, not because it failed.
  - **`copy` only, dropping `symlink`** — recommended in session and overruled. It is the cheaper half by a wide margin: copies are more entries in the same `path → bytes` mapping that `apply_overlay` already writes and `content_inventory` already hashes, needing no new write primitive, no second inventory shape, and no change to the traversal guard. The CEO chose to offer both because the convention being adopted offers both.
  - **Auto-detecting the platform and falling back** — rejected on NFR-1, above.
  - **Symlinking into a cache outside the project**, as the reference installer does — rejected: dev-ready generates the project that holds the content, and writing outside the target directory is something dev-ready does not do.
- Consequences: This is the largest overlay change since FR-26, and for the same reason — it touches the write path, the stamp inventory, `verify`, `upgrade`, and a migration, which is why it takes a version to itself. `symlink` mode produces a project whose agent directories are machine-local: a collaborator who clones it on Windows without `core.symlinks` gets no working agent directory, and the generation report must say so at the moment the mode is chosen. Junction targets are absolute, so moving a `symlink`-mode project breaks its links until `upgrade` is re-run. The [[Pointer Stub]] glossary entry is retired to historical status. dev-ready now carries a mode that ADR-015 spent two rejections avoiding; reopening *that* is settled, but the operational costs above are permanent and belong in the user-facing report, not only here.
