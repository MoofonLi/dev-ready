## What v0.11 ships

v0.11 is the setup, selection, and reach version. A generated project’s
development method is now chosen and named, every optional Category is shown
to every interactive user, a project can be configured without reading `.env`
by hand, seventy-four Design References are selectable, the MIT notice travels
with the copied skills, and the Generation Skill installs as a plugin in two
ecosystems. The stamp stays at version 5. There is no new runtime dependency
and no change to the base template’s role.

### Engineering Flow and interactive rework (FR-42, [ADR-024](../decisions/adr-024-engineering-flow-selection-spine.md))

- The development loop is the **Engineering Flow**, asked first and named for
  its source. The live id is `mattpocock`. `superpowers` and `addyosmani` appear
  as Announced Flows — dimmed `(coming soon)` rows the cursor cannot land on.
- `--flow` is the documented spelling of the existing `--development-loop`
  argument. Both are accepted. `--flow spec-loop` exits 2 and names
  `mattpocock`. A v5 stamp that records `spec-loop` still resolves through a
  stamp-scoped alias.
- Interactive `init` is: project name → Engineering Flow → Security → Quality
  → Design → Token Optimize → Agent Targets → confirmation. There is no
  Default Set question and no Dev checkbox. Enter through every prompt
  produces the Default Set, byte-identical to `--yes`.
- A flag answers only its own question. A lone `--security security-audit`
  selects the Default Set plus that item, not the whole catalog. `--agents`
  no longer marks the catalog selection resolved.

### CLI presentation (FR-44)

- Every prompt uses one `questionary` style. Announced Flows are disabled
  rows. The generation report is a counted summary in plain text, with no
  colour and no new runtime dependency. Non-TTY output stays free of escape
  sequences.

### `setup-project` and Flow Chain guidance (FR-39, FR-43, [ADR-026](../decisions/adr-026-setup-project-is-project-infrastructure.md))

- `setup-project` is written into every generated project as Overlay
  Infrastructure, not as a Catalog Item and not as a path of the selected
  flow. It interviews for the superuser, email, and Sentry, and the selected
  flow contributes its own sections. It explains and stops — it never runs a
  destructive command.
- The generated `AGENTS.md` section is `## Engineering Flow`. The chain is
  `setup-project` → `grill-with-docs` → `to-spec` → `to-tickets` →
  `implement` → `improve-codebase-architecture`. Steps are user-invoked. A
  change that adds no observable behaviour may start at `implement`.
- `docs/agents/mattpocock.md` is written only when that flow is selected.
- The generation report names `setup-project` before `docker compose watch`.

### Design Reference set and MIT notices (FR-40, FR-41, [ADR-009](../decisions/adr-009-manifest-vendored-provenance.md) as amended, [ADR-018](../decisions/adr-018-spec-loop-spine-and-default-set.md) as amended)

- All 74 `DESIGN.md` documents at the pinned `awesome-design-md` commit are
  ordinary Design Category items, derived by a maintainer script. Identifiers,
  titles, and the Generation Skill’s `### design items` section are owned by
  that script. `--design design-stripe,design-linear` is unchanged.
- A docs-only selection collapses to one line in `implement/SKILL.md`. A
  skills or MCP Enhancement keeps its own bullet.
- The upstream MIT `LICENSE` travels with every copied source: the three
  directory-shaped MIT vendors plus `docs/design-md-LICENSE.md` when any
  Design Reference is selected. No legal conclusion is drawn in any
  user-facing document.

### Plugin distribution (FR-45, [ADR-027](../decisions/adr-027-repository-is-the-plugin.md))

- Four files at the repository root describe this repository as one plugin:
  `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`,
  `.codex-plugin/plugin.json`, and `.agents/plugins/marketplace.json`. All
  four resolve to the existing `skills/dev-ready/` directory. There is no
  second copy of the skill.
- `npx skills add MoofonLi/dev-ready --skill dev-ready` remains the
  documented primary channel. The catalogs are additional.
- Each manifest’s `version` is guarded equal to `dev_ready.__version__`. The
  repository root is a shipping surface: a top-level plugin component
  directory other than `skills/` fails the suite.

## Upgrade from v0.10 ([ADR-014](../decisions/adr-014-truthful-overlay-lifecycle-state.md))

The stamp stays at version 5, so `dev-ready upgrade` re-applies the v0.11
overlay without a migration and without asking the user to choose again. A
stamp that records `spec-loop` resolves to `mattpocock`. Base Provenance stays
immutable; only Overlay Currency advances.

What arrives as new managed files: `setup-project` (Canonical Content and a
Pointer Stub at each selected Agent Target), the MIT notice files, and
`docs/design-md-LICENSE.md` when any Design Reference is selected. An
untouched `AGENTS.md` is replaced.

If the project selected the two shipped Design References and nobody edited
`implement/SKILL.md`, that file is replaced too: the mounted block becomes one
docs line, and the two descriptions lose their light-versus-dark wording.

There is no v0.10-style reach limit. Every new path is a managed file.
Edited files stay edited. A dry run reports the whole plan; a failure rolls
writes and deletions back together; a repeat successful upgrade plans no
further change.
