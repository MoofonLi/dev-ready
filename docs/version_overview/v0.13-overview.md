# v0.13 Overview — dev-ready

Release: v0.13.0 | Status: Released
Scope: FR-48 `addyosmani` as the third Engineering Flow; FR-49 Token Optimize
addition; FR-50 Flow Selection Criteria; FR-51 CLI presentation second pass;
FR-52 Generation Skill interview; FR-53 Occupied Target; FR-54 README rewrite;
architecture hygiene (no FR); permanent FR-22 N-1 → N gate

## What v0.13 ships

v0.13 is the third-flow, occupied-destination, and README version. A developer
can choose among three Engineering Flows, generate into a directory that
already has content, and finish the README in one screenful with a recorded
capture of the real CLI. The stamp stays at version 5. `rich` is a new runtime
dependency. The pinned base template is unchanged.

### Flow Selection Criteria (FR-50, [ADR-024](../decisions/adr-024-engineering-flow-selection-spine.md) as amended)

- Every declared Engineering Flow carries `choose_when`: an ordered list of
  short strings naming the situations it suits. `description` is the one-line
  menu label. Both existing flows' descriptions were rewritten a second time
  in two versions so the criteria could carry the situations.
- A traceability guard fails the build if a criterion names a step the flow
  does not ship. Announced flows carry no `choose_when`.

### Generation Skill interview (FR-52, [ADR-023](../decisions/adr-023-upstream-facts-drift-guard.md) as amended)

- The Generation Skill states the fixed stack as known facts that must not be
  asked — FastAPI, React, PostgreSQL, Docker Compose; every project has a
  frontend; the frontend is React — under the ADR-023 drift guard. The
  interview is a fixed must-ask list: project name and destination; how much
  the developer wants to steer, quoting `choose_when` verbatim; accounts /
  payments / personal data; automated React health checks or browser tests;
  interface ambition and which product's design language to reference; and
  which coding agents are in use.
- `react-doctor` and `webapp-testing` are must-asks on the ground that every
  project has a React frontend. They stay off by default.

### CLI presentation, second pass (FR-51, [ADR-003](../decisions/adr-003-cli-ux-and-errors.md) as amended)

- The flow comparison, the pre-generation confirmation, and the generation
  report are three frameless Static Screens rendered with `rich`. Colour drops
  when `NO_COLOR` is set or stdout is not a terminal; every screen stays
  fully legible without it. Prompts, progress, `check`, `upgrade`, and errors
  are unchanged.
- Next steps sit above the credential and overlay blocks. Nineteen
  standard-compliant agents collapse to a count with three examples.
- `questionary` still owns every interactive prompt. Framed boxes were
  considered and declined.

### Occupied Target (FR-53, [ADR-031](../decisions/adr-031-occupied-target.md))

- `init --dir .` accepts a destination that already has content when no
  top-level entry collides. Pre-existing entries are never touched, moved, or
  removed. Collision is name equality at the top level and is exit 4, naming
  every colliding entry. The failure state is always a set of whole entries,
  never a half-written file.
- An absent or empty destination still finalizes with one atomic rename. An
  Occupied Target finalizes with a bounded sequence of atomic per-entry moves
  and best-effort restoration.
- When the positional project name is omitted, it defaults to the destination
  directory's name.
- `check` no longer reports a project's own `.git` as an upstream leak. The
  forbidden-path rule still applies at generation time.

### Third Engineering Flow (FR-48, [ADR-024](../decisions/adr-024-engineering-flow-selection-spine.md) as amended, [ADR-029](../decisions/adr-029-a-flow-declares-its-own-shape.md))

- `addyosmani` is selectable. The last `(coming soon)` row is gone. Its
  `invocation` is model-driven; its chain runs from a written spec through
  implementation, production-readiness steps, and `shipping-and-launch`.
- A step's template source is its `paths` entry, so two flows can ship a
  skill of the same name with different content.

### Token Optimize addition (FR-49, [ADR-008](../decisions/adr-008-integration-modes.md))

- Token Optimize gained `i-have-adhd`, which keeps agent answers structured
  and scannable. The Category description widened to cover output legibility
  as well as token spend. The Category id is unchanged.

### Architecture hygiene (no FR, [ADR-029](../decisions/adr-029-a-flow-declares-its-own-shape.md) as amended)

- Flow Convention and Setup Contribution left a Python dict keyed by flow id
  and became per-flow template files referenced from the manifest. Adding a
  flow is a data change plus assets, which is the property ADR-024 recorded.
- Generation Intent — `ProjectSelection` and `Answers` — left the terminal
  input package. Eleven production modules no longer import `prompts` to read
  catalog selection. User-visible behaviour is unchanged.

### README rewrite (FR-54, [ADR-023](../decisions/adr-023-upstream-facts-drift-guard.md) as amended 2026-08-30, [ADR-016](../decisions/adr-016-language-boundary.md))

- `README.md` is under 100 lines: one sentence, the command, a Recorded
  Capture of interactive `init`, a five-row table of what a project receives,
  a three-line quickstart, the three-flow comparison quoting `choose_when`,
  and links out. The flag table, exit codes, and `upgrade` semantics live
  only in `docs/cli-spec.md`.
- The capture is recorded from a committed VHS tape of the real CLI, never
  drawn. It carries no load-bearing claim: every fact it shows is also in
  guarded text on the same page. Re-recording is a named human step, not a
  CI job.
- `README-pypi.md` received the same cut, with absolute links, so the
  duplication left the repository rather than moving within it.
- `README.zh-TW.md` stayed a focused overview. It gained the capture, the
  occupied-destination run-once fact, and three selectable flows.

## Upgrade from v0.12 ([ADR-014](../decisions/adr-014-truthful-overlay-lifecycle-state.md), [ADR-031](../decisions/adr-031-occupied-target.md))

The stamp stays at version 5, so `dev-ready upgrade` re-applies the v0.13
overlay without a migration and without asking the user to choose again. No
new selection input is required. Base Provenance stays immutable; only
Overlay Currency advances.

The third Engineering Flow and the new Token Optimize item are available to
select on a fresh `init`. They are not applied to an existing project unless
the user selects them on a later generation. `upgrade` cannot add a flow the
stamp did not record.

`check` on a v0.12 project that has since been placed under version control
no longer reports `.git` as drift. Occupied-destination `init` is new
behaviour on this CLI; it does not change `upgrade`.

A dry run reports the whole plan; a failure rolls writes, deletions, and
links back together; a repeat successful upgrade plans no further change.

## Deviations from the accepted specs

- **The 0.13.0 CHANGELOG entry landed in the FR-54 spec commit**, before
  Phase 6 implement. The plan said no earlier phase may write it. The
  implement tickets found the committed text already covering the seven
  required items, with no Breaking changes section and with the `.git` fix
  under Fixed and occupied-destination under Changed, so it was left in
  place rather than rewritten.
- **`README-pypi.md` received the same cut as `README.md`.** The version
  plan said only to check it for consistency. Moofon authorized the
  widening on 2026-08-30; FR-54's stated defect was two copies with no
  drift guard, and leaving the PyPI page as a third copy would have
  shipped the defect and a fix for it in the same release.
- **The Recorded Capture was produced with the official VHS container**
  (plus git and a local install of this package) because native `vhs`,
  `ttyd`, and `ffmpeg` were not on PATH. The committed artifacts are the
  tape and the GIF; the recorder image is not in the repository. Size at
  recording: 1,032,116 bytes (0.984 MiB).
- **Phase 4 landed both deepenings it was allowed** (Flow Convention / Setup
  Contribution, then Generation Intent). User-visible behaviour was
  unchanged, as the phase required.
