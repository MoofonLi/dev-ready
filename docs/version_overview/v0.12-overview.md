# v0.12 Overview — dev-ready

Release: v0.12.0 | Status: Released
Scope: FR-46 Skill Links replace Pointer Stubs; FR-47 `superpowers` as the
second Engineering Flow, a declared invocation model, and the flow
recommendation; permanent FR-22 N-1 → N gate

## What v0.12 ships

v0.12 is the delivery-and-second-flow version. Every selected Agent Target
receives one Skill Link per skill instead of a Pointer Stub, and a generated
project can be built around either of two Engineering Flows. The stamp stays
at version 5. There is no new runtime dependency and no change to the base
template's role.

### Skill Links (FR-46, [ADR-028](../decisions/adr-028-skill-links-replace-pointer-stubs.md))

- Each selected Agent Target's skills directory holds one link per canonical
  skill, pointing at `.agents/skills/<name>`. On macOS and Linux that is a
  relative symbolic link; on Windows it is an elevation-free directory
  junction. There is no copy mode, no Pointer Stub, no delivery prompt, and
  no `--skill-delivery` flag.
- The links are machine-local and excluded from version control by a nested
  `.gitignore` inside each Agent Target skills directory. A cloned project
  keeps Canonical Content and that ignore file; one `uvx dev-ready upgrade`
  recreates the links. `setup-project` cannot bootstrap this, because it
  reaches Claude Code through the same link.
- A filesystem that cannot hold links cannot receive a project with a
  selected Agent Target, where v0.11 could. An explicit `--agents none`
  project needs no links and still works. `init` probes during verify and
  exits 5 before writing anything; `upgrade` of an existing project on such
  a filesystem exits 9 after a complete rollback.
- Links are derived state and are never inventoried. `check` reports a
  missing or unresolvable link as drift (exit 7). `upgrade` creates missing
  links, repairs junctions broken by a project move, and retires untouched
  Pointer Stubs from a v0.11 project in the same transaction. A hand-edited
  stub is preserved and its link is not created.

### `superpowers` and the flow recommendation (FR-47, [ADR-024](../decisions/adr-024-engineering-flow-selection-spine.md) as amended, [ADR-029](../decisions/adr-029-a-flow-declares-its-own-shape.md), [ADR-030](../decisions/adr-030-executable-vendored-content.md))

- Interactive `init` offers two selectable Engineering Flows and one
  announced `(coming soon)` row. `mattpocock` is still the `--yes` default.
  `superpowers` is selectable; `addyosmani` is not.
- Selection criteria, not feature lists: `mattpocock` is "You start each
  step yourself, and the work stays in one session." `superpowers` is "The
  agent starts each step on its own, and implementation can be split across
  fresh subagents." The same strings appear in the catalog, the interactive
  prompt, and the Generation Skill.
- A flow declares its own chain and its own mount roles. Superpowers forks
  at step four — `subagent-driven-development` or `executing-plans` — and
  that fork is a choice, not a skipped step. `setup-project` remains the
  unconditional head of every chain.
- A `superpowers` project's plans live under `docs/superpowers/plans/` and
  its design documents under `docs/superpowers/specs/`. Executable files
  arrive executable on macOS and Linux; on Windows, execution depends on
  the shell.
- `--flow superpowers` no longer exits 2. `--flow addyosmani` still does.
  A retired Dev item id exits 2 naming the mandatory Engineering Flow
  without naming which one.

## Upgrade from v0.11 ([ADR-014](../decisions/adr-014-truthful-overlay-lifecycle-state.md), [ADR-028](../decisions/adr-028-skill-links-replace-pointer-stubs.md))

The stamp stays at version 5, so `dev-ready upgrade` re-applies the v0.12
overlay without a migration and without asking the user to choose again. No
new selection input is required. Base Provenance stays immutable; only
Overlay Currency advances.

What retires once: the old pointer files at each selected Agent Target,
replaced by Skill Links, when every recorded file in that stub directory is
untouched. A hand-edited pointer file is preserved and reported; its link
is not created until that directory is empty.

A filesystem without link support cannot upgrade an existing project that
selected an Agent Target. The attempt exits 9, rolls back completely, and
leaves the project on v0.11 until it is moved somewhere links work.

A dry run reports the whole plan; a failure rolls writes, deletions, and
links back together; a repeat successful upgrade plans no further change.

  directory's `fr-NN-<slug>` convention has no slot for a documentation-and-

  than normalized by the skip.

  be upgraded at all); two Phase 2 escapes (the retired-id error still
  naming `mattpocock`, and the Generation Skill claiming every project
