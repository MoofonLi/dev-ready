# v0.9 Overview — dev-ready

Release: v0.9.0 | Status: Released
Scope: FR-30 Category-first selection; FR-31 mandatory Spec Loop and Default
Set; FR-35 generated Handoff Protocol retirement; permanent FR-22 N-1 → N gate

## What v0.9 ships

dev-ready v0.9 changes how users choose the AI-development overlay and what a
project receives when they accept the defaults. It adds no runtime dependency,
does not change the manifest-pinned base template, and preserves all-or-nothing
generation and upgrade.

### Category-first selection (FR-30, ADR-017)

- Category replaces Component as the user-facing selection axis. The declared
  Categories are Dev, Security, Quality, Design, and Token Optimize; Component
  remains only as the internal grouping that decides where files are written.
- Dev holds the mandatory development-loop single-select and may also hold
  optional Enhancements. The other Categories contain only optional
  Enhancements and may be declined entirely. Category and item identifiers come
  from the manifest rather than from branches in the CLI.
- Non-interactive selection uses `--categories`, `--development-loop`, and the
  per-Category flags `--dev`, `--security`, `--quality`, `--design`, and
  `--token-optimize`. `all`, `none`, and comma-separated identifiers retain
  their established meanings; Agent Targets remain an independent `--agents`
  selection.
- The old Component-shaped flags are rejected with exit 2 and a replacement or
  removal explanation. They are not accepted as aliases because Component intent
  cannot be translated into Category intent without guessing.
- `.mcp.json` is infrastructure rather than a selectable item. It is written
  when a selected Enhancement needs MCP configuration and omitted otherwise.
  The two DESIGN.md references are independent Design Enhancements.
- Fresh projects use stamp version 5, recording Categories, the resolved
  development loop, Enhancements, Agent Targets, pins, and managed inventory as
  Overlay Currency.

### Mandatory Spec Loop and lean defaults (FR-31, ADR-018)

- Every generated project receives the Spec Loop. The manifest records it as
  the single current option in the mandatory Dev Category, so the stamp names
  the resolved loop and a future second loop remains a data addition.
- The loop now contains the complete execution cycle, including `implement`
  with TDD, diagnosis, and two-axis code review. Its former bundle and
  dependency identifiers are no longer independently selectable.
- Accepting the defaults, including `init PROJECT --yes`, produces the lean
  Default Set: the Spec Loop plus the project's `docs/architecture.md` and
  `docs/requirements.md` skeletons. No Enhancement is selected implicitly.
- `--categories all` is the explicit whole-catalog selection for users who want
  every Enhancement. The former ten-item catalog cap is retired; the enforced
  limit applies only to the Default Set.
- The opt-in `setup-all` Dev Enhancement can configure an existing project
  later, but generation already writes working local defaults. It is never a
  prerequisite and generated content does not instruct users to run an
  Enhancement they did not select.

### Generated Handoff Protocol retirement (FR-35, ADR-020)

Fresh v0.9 projects no longer contain the seven-role Handoff Protocol, its
Protocol Configuration, gate templates, ticket scaffold, or execution-report
skeleton. Its Component and flags are removed, and no smaller scaffold replaces
it. Generated projects describe one process: the mandatory Spec Loop.

ADR-020 changes the generated product surface only. It did not change how this
repository was developed. Four days later, ADR-021 independently retired the
repository's internal Handoff Protocol in favor of the Spec Loop alone;
`docs/handoff/<version>/` remains the home of version plans and working tickets.

## Upgrade from v0.8 (ADR-014)

`dev-ready upgrade` migrates a v0.8 project to the v0.9 overlay without asking
the user to choose again:

- the version 4 stamp advances to version 5, deriving Categories from its
  recorded items and recording the mandatory development loop;
- a project that previously declined the Spec Loop gains the complete loop,
  while a project that selected it carries that choice forward;
- untouched Handoff Protocol files, the removed `project-orientation` skill and
  Pointer Stubs, and an unneeded base MCP configuration are deleted;
- any obsolete managed file the user edited is preserved unchanged and reported
  as divergence instead of being deleted;
- immutable Base Provenance and upstream application content remain untouched
  while Overlay Currency advances.

Dry run reports the complete write-and-delete plan without changing a byte. A
failure rolls additions, replacements, and deletions back together, and a
repeat successful upgrade plans no further change. The permanent network-tier
gate exercises this path from the released `dev-ready==0.8.0` artifact and
finishes with a clean `check`.

  and drift guard (FR-33), and the interview-driven generation skill (FR-34).
