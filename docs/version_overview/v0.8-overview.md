# v0.8 Overview — dev-ready

Release: v0.8.0 | Status: Released
Scope: FR-26 multi-agent render targets; permanent FR-22 N-1 → N gate

## What v0.8 ships

dev-ready v0.8 makes generated agent guidance portable without multiplying its
authoritative copies. It adds no runtime dependency and does not change the
manifest-pinned base-template or all-or-nothing generation guarantees.

### Canonical Content and Agent Targets

- Canonical skills are always written once under `.agents/skills/`, and project
  rules are always written once to `AGENTS.md`. Cursor, Codex, Cline, Zed,
  OpenCode, and other standard-compliant agents need no declared Agent Target.
- `--agents` independently selects manifest-declared Agent Targets by a
  comma-separated identifier list, `all`, or `none`. v0.8 declares `claude` and
  `windsurf`; both are enabled by default.
- A selected Agent Target receives ordinary Pointer Stub files at its native
  discovery path. Each stub carries the skill name and description and directs
  the agent to Canonical Content. Stubs are neither symbolic links nor content
  copies.
- Claude Code receives `.claude/skills/` stubs, a `CLAUDE.md` import of
  `AGENTS.md`, and project-level `.mcp.json` when MCP items are selected.
  Windsurf receives `.windsurf/skills/` stubs; its MCP configuration is
  user-global, so dev-ready reports the required manual configuration and never
  writes outside the generated project.
- `--agents none` still produces complete Canonical Content and creates no
  Agent Target directory.

### Component and stamp migration

- The Handoff Protocol component is named `handoff`; `--no-handoff` is its
  current flag. `--no-agents` remains a deprecated alias for one version and
  emits a warning.
- The project stamp is version 4. It records selected Agent Targets as Overlay
  Currency and records the Handoff Protocol under `components.handoff`.
- A project generated by v0.7 upgrades without new input. Claude Code is
  inferred as its sole Agent Target, Canonical Content is written, and untouched
  superseded Claude files are transactionally replaced by Pointer Stubs.
- User-edited superseded files are preserved. Their stub writes are skipped and
  the resulting divergence is reported for manual reconciliation. Dry runs are
  non-mutating, failures roll additions, replacements, and deletions back
  together, and a repeat upgrade is a no-op.
- Overlay-only upgrade preserves upstream application files and immutable Base
  Provenance while advancing Overlay Currency. The permanent network-tier gate
  exercises this migration from the released `dev-ready==0.7.0` artifact.

## Language boundary and withdrawn FR-25

FR-25 was withdrawn on 2026-07-26 before implementation, and its number is
retired. v0.8 contains no CLI localization, locale detection, language flag,
environment variable, message catalog, or stamp language field. ADR-016 fixes
the boundary: everything dev-ready emits and generates remains English.

Traditional Chinese is provided only through the focused repository overview
`README.zh-TW.md`, which explains stable product facts and points to the English
README and CLI specification for the complete reference. The withdrawal is
settled history, not deferred v1.0 work.

## Review and verification record

Phases 1–3 implemented and independently verified the component rename, stamp
v4 compatibility, Canonical Content rendering, Agent Target selection matrix,
Pointer Stub safety, and the v0.7 migration. Phase 4 reviewed the consolidated
release surface, completed the version bump, and released v0.8.0.

The release gate must pass, in order, `uv sync --dev`, offline `uv run pytest`,
`uv run ruff check .`, and `uv run pytest -m network`. CI additionally covers
vendored drift and notices, real-generation health, and the permanent v0.7 →
v0.8 migration. All review gates approved the terminal release, and release
metadata is synchronized at 0.8.0.

## Deferred scope

- v1.0 after the real-users gate: FR-27, a standalone full-stack Next.js
  template, and reconsideration of the Web UI.
- Still deferred: additional Agent Targets, per-agent content variants,
  symbolic-link or per-agent-copy installation modes, multiple Handoff Protocol
  presets, and catalog growth beyond the 10-item cap.
- CLI localization is not deferred scope. FR-25 is withdrawn and reopening it
  requires new external non-maintainer demand evidence.
